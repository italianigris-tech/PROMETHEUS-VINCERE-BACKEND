# Kinetic Causal Chain

## Governing rule

Animation is an evidence-backed treatment of meaning. It is never a random preset applied after layout.

```text
semantic token evidence
  -> Font JSON typography authority
  -> scene-aware placement candidate
  -> compatible kinetic trait selection
  -> frame-addressable render program
  -> foreground/background composite
  -> transition continuity
  -> final frames
```

Each arrow must leave a machine-readable receipt. A missing receipt means the downstream treatment is ineligible.

## Current vertical slice

Currency, percentage, quantity, and year-like tokens are parsed as numeric evidence. Currency and percentage evidence receive the strongest count-up bias. Plain quantities and years require semantic emphasis before selection. This is a bias, not a rigid rule.

The count-up trait is eligible only when:

- the token came from the authoritative semantic token stream;
- its chunk has a compiled Font JSON binding;
- the trait contract passes channel and conflict validation;
- placement passes all existing scene, face, safe-zone, and geometry hard gates.

The trait may bias a measured lower or center 9:16 placement. It cannot override those hard gates. Font JSON remains authoritative for family, weight, hierarchy, spacing, color, and measured geometry.

The emitted kinetic receipt identifies semantic evidence, Font JSON profile and metrics fingerprint, placement intent, selected trait, deterministic executor, and target token IDs. The Remotion renderer uses the receipt and frame number only. Browser timers, hover state, and unseeded randomness are excluded.

## Registry law

`kinetic_trait_registry.json` is the trait source of truth. Every trait declares scope, roles, owned channels, requirements, conflicts, render mode, cost, and readability limits. Registry validation rejects duplicate IDs, unknown conflicts, asymmetric conflicts, and duplicate channel declarations. Compatibility rejects explicit conflicts and channel collisions.

## Proof composition

`KineticCausalChainProof` is the first 1080x1920 vertical tracer bullet. It renders source-grounded `$10,000` evidence through a Font JSON profile, lower-frame placement, deterministic count-up, still-image background, and supportive foreground accent.

Run:

```powershell
npm --workspace remotion-app run studio
```

Open `http://localhost:3011/?/KineticCausalChainProof`.

## Isolated phenotype studies

Standalone animation studies may exist for renderer development, but they are not registered as production MAUL previews and are not evidence of Font JSON provenance. A production preview must enter through `MaulShort`, consume a schema-validated manifest, and carry compiler-issued typography, copy, camera, transition, and trait receipts.

The registry distinguishes contract-only phenotypes from typed executors. Numeric count-up remains the first complete semantic-evidence-to-render-receipt vertical slice; a registry contract alone does not make a phenotype planner-eligible.

## Expansion order

1. Extract remaining reference phenotypes into independently executable traits.
2. Add semantic eligibility policies for dates, ratios, rankings, quotations, corrections, and replacements.
3. Introduce a background plan with subject-safe zones, luminance, palette, depth role, and evidence provenance.
4. Introduce transition continuity contracts between adjacent semantic beats and background states.
5. Add deterministic supportive asset selection tied to the same semantic evidence.
6. Add pairwise visual evaluation so emergent hybrids must beat their parent treatments before promotion.

Background motion, foreground motion, and transitions remain separate planning concerns. The compiler may coordinate them through shared timing and evidence, but no concern may silently own another concern's CSS or render channels.
